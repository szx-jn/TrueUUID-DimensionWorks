# 1.0.9 自动继承离线存档

## 基线与范围

本 fork 以社区版 TrueUUID 1.0.9 的 Forge 1.20.1 源码提交
9c4479a758a3347732a1172c52b4edae8be9b336 为基线，使用 Java 17、
Gradle 8.8 和整合包现有的 Forge 47.4.23。发布版本为
1.0.9-dimensionworks.1。保留上游 GNU LGPL 3.0 许可和作者署名。

保留 1.0.9 的认证协议、客户端会话上报、Mojang/MSL 校验和旧 TOML
白名单键。变更集中在认证成功后的玩家数据继承，不能因为认证失败、
近期 IP 容错或按名字查询公开皮肤就自动移动存档。

## 自动继承规则

默认开启 auth.autoMigrateOfflineData。首次通过真实会话校验的账号，
在 Forge 继续登录、LuckPerms 预加载和玩家文件读取之前，继承同名离线
UUID 的数据。使用登录请求的原始名字计算离线 UUID，避免大小写校正
导致找不到旧档。与已有认证 UUID 绑定冲突时停止继承。

支持上游已有路径：playerdata、playerdata_old、Cosmetic Armor、原版
advancements/stats、Open Parties and Claims、FTB Chunks/Essentials/
Teams/Quests、CustomNPCs 和 FTB Ranks。玩家 NBT 只调整根 UUID，
保留背包、末影箱、位置、经验和 ForgeCaps。FTB 成员、奖励领取和
团队引用须同步改为新玩家 UUID，并刷新已加载的相关缓存。

自动模式不覆盖不同的目标进度。如果目标文件与继承结果完全一致，
允许归档重复旧文件；不同、缺乏对应关系或 UUID 引用冲突时停止登录，
保留两边原档并提示管理员处理。已完成继承后再次连接不会重做迁移。

## 文件事务与恢复

先完整备份本次涉及的旧文件、已存在目标文件及共享引用，再写目标，
刷新相关缓存，最后把旧文件归档。每次使用独立备份目录，保存 SHA-256
摘要和事务状态；不覆盖旧备份，不直接丢弃旧存档。

失败时恢复本次涉及的原文件和缓存。进程异常退出留下的活动事务在
下次服务器加载存档前恢复；发现文件在事务之外被修改时停止恢复，
保留备份并报错。拒绝符号链接、路径越界、过大文件和并发迁移。

迁移期间目标 UUID 与离线 UUID 都必须不在线。只检查已知玩家路径和
相关 FTB 文本目录，不扫描区块文件、不加载区块、不生成实体，没有
常驻定时扫描。磁盘访问只发生在存在待迁移数据的连接或管理命令中。

## 管理接口与发行

普通连接不再需要手动执行继承和清理命令。关闭自动继承后保留旧版
确认流程。管理命令默认也采用保全模式；明确选择覆盖或保留目标时，
仍需先备份双方并归档旧数据，不能在玩家在线时运行。

正式 JAR 仅由本 fork 的手动 GitHub Actions 工作流构建、校验和发布。
整合包引用固定 GitHub Release 标签和资产，客户端与服务端同步引用。
本地 JAR 只用于隔离开发验证，不部署到正式服。
